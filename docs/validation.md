# v0.1.0-dev 验证记录

日期：2026-11-07。以下记录区分程序测试、实际图像产出与尚未完成的制作阶段。

## 已实际执行

- 启动独立 Codex CLI worker，运行记录中的执行模型为 `gpt-6-astra`，进程退出码为 0。
- 使用 worker 内置的 `image_gen` 工具分别生成科研设备箱、检修灯、控制台，共三次真实图像生成调用。
- 三张图片成功保存、解码与查看；原始图与工作副本 SHA256 相同。
- 原生生图工具没有暴露实际图像模型 ID，记录为 `null`，不将执行模型当作图像模型。
- 使用工作流 CLI 将真实图片回执登记为候选，状态均为 `concept_review`，批准字段均为 `null`。
- 对真实项目请求建模任务包时，程序因尚无图片批准而拒绝；没有启动 Blender 制作。
- 本地设计确认页在桌面与手机宽度下显示三张原比例图片，无横向溢出。

## 合成测试

运行：

```shell
python -m unittest discover -s tests -v
```

53 项测试中 51 项通过，2 项文件符号链接用例因本机 Windows 权限限制跳过。目录 junction 用例正常执行并通过。

测试使用临时文件、合成图像与模拟 worker，覆盖：

- 没有逐图人工批准时不能启动建模；主题选择不构成图片批准。
- 参考图发生变化后原批准失效；新批准清除旧交付接受状态。
- 任务、资产、阶段与图片哈希一致性；缺失或伪造回执不能表示成功。
- 空交付记录、缺失文件、变化后的模型依赖、错误 GLB 文件头或长度不能通过接收。
- 图片结构与哈希、路径越界、Windows 设备名称、junction、并发状态修改保护。
- worker 退出但没有结果回执、执行超时、失败后恢复，以及“不批准自身输出”。

这些测试验证协调程序的行为。它们不验证 Blender 文件真实可打开、模型结构、导出外观或审美质量。
